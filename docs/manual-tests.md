# 実機検証（PT）の手順

テスト項目タブの「手動・実機検証」。実装担当が手順を書き、人間が実行して結果（OK / NG、メモ、録画・スクリーンショット・数値）を返す。露出の確認は必ず別ソフトの録画（OBS 等）をコマ送りして行う。

## 共通の準備

```sh
python scripts/build.py            # 実行中のマシン向け（bin/publish/<rid>/）
python scripts/install.py          # 既定のフォルダへ（Windows はデスクトップに Hider.lnk、Ubuntu は .desktop）
```

- 設定ファイル: Windows `%USERPROFILE%\.hider\areas.json`、Ubuntu `~/.hider/areas.json`。各 PT の前に消すと初期状態から始められる。
- ログ: ターミナルから `Hider --verbose` で起動すると標準エラーに出る。NG の時は添えてほしい。

## Windows 11（Step 3）

| ID | 手順 | 合格基準 | 記録するもの |
|---|---|---|---|
| PT-01 | 起動 → タスクバーのトレイアイコン（モザイク柄）を左クリック → Esc → 右クリック | 左右とも同じ 4 項目（新しいエリアを追加 / すべてのエリアを編集 / すべてのエリアを削除… / 終了）がカーソル付近に出る。エリア 0 個では「すべてのエリアを編集」「すべてのエリアを削除…」が無効 | 左右それぞれのスクリーンショット |
| PT-02 | 「新しいエリアを追加」→ 本体をドラッグして移動 → 右下ハンドルでリサイズ → パターンを「塗りつぶし」に → ✓ 完了 → トレイ「終了」→ 再起動 | 同じ位置・サイズ・パターンで隠しモードで復元される | 終了前と再起動後のスクリーンショット、areas.json |
| PT-03 | Hider 起動中にもう一度 Hider を起動 | 2 つ目は何も出さずに即終了。トレイアイコンは 1 つ | タスクマネージャのプロセス数 |
| PT-04 | 塗りつぶしのエリア（色 #68768A）の areas.json の opacity を 0.5 にして再起動 → 1.0 に戻して再起動 | 0.5 で下が半分透ける。1.0 で完全に隠れる（設定ポップアップは Step 5 で追加） | スクリーンショット 2 枚 |
| PT-05 | エリアを置いた状態でメモ帳・ブラウザをクリックして前面に出す | エリアが常に上に残る。全画面アプリとの前後は記録のみ | 結果メモ |
| PT-06 | メモ帳に入力中に Hider を起動（エリア復元あり）、続けてトレイから「新しいエリアを追加」 | 起動・復元時にメモ帳のフォーカスが奪われない（入力が続けられる）。新規追加は編集モードで出る | 結果メモ |
| PT-07 | 100% と 150% のモニタを並べ、エリアを 100% 側から 150% 側へドラッグして離す | ツールバーのサイズ表示（物理 px）と見た目が整合する。離した後に大きさが跳ねない | 両モニタでのスクリーンショットとサイズ表示 |
| PT-08 | エリアを移動した直後（✓ を押さずに）サインアウト → サインイン → Hider 起動 | 直前の移動が残っている（ドラッグ終了時に保存済み） | 結果メモ |

## 作業コンテナでの確認（参考）

Xvfb（コンポジタなし）で、起動時の復元、画面外エリアの主画面中央への補正、ダブルクリックでの編集モード、ツールバー表示（日本語）、本体ドラッグ、Esc での終了と保存を確認済み（2026-10-11）。コンポジタがないため編集時の余白は白く見える（実機では透明）。
