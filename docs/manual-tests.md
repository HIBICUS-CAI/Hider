# 実機検証（PT）の手順

テスト項目タブの「手動・実機検証」。実装担当が手順を書き、人間が実行して結果（OK / NG、メモ、録画・スクリーンショット・数値）を返す。露出の確認は必ず別ソフトの録画（OBS 等）をコマ送りして行う。

## 共通の準備

```sh
python scripts/build.py            # 実行中のマシン向け（bin/publish/<rid>/）。Ubuntu では python3
python scripts/install.py          # 既定のフォルダへ（Windows はデスクトップに Hider.lnk、Ubuntu は .desktop）
```

- 設定ファイル: Windows `%USERPROFILE%\.hider\areas.json`、Ubuntu `~/.hider/areas.json`。各 PT の前に消すと初期状態から始められる。
- ログ: `--verbose` で起動すると標準エラーに出る。Windows の Hider.exe は GUI アプリなのでコンソールには出ない: `Hider.exe --verbose 2> hider.log` のようにファイルへリダイレクトする。Ubuntu は端末から `Hider --verbose`。NG の時は添えてほしい。

## Windows 11（Step 5）

モザイクの確認には、下で動画や文字が動くアプリ（ブラウザで動画を再生、メモ帳に入力など）を使う。録画は OBS（画面キャプチャ、60 fps）で行い、コマ送りで確認する。

| ID | 手順 | 合格基準 | 記録するもの |
|---|---|---|---|
| PT-09 | ブラウザで動画を再生し、その上に新しいエリア（モザイク / ピクセル化、更新間隔 100 ms）を置いて ✓。OBS で 30 秒録画 | モザイクが動画に追従する。録画のどのコマにも素の内容が映らない | 録画ファイル（または問題のコマのスクリーンショット） |
| PT-10 | PT-09 の状態で OBS の画面キャプチャと Teams / Zoom の画面共有を行う | 共有先・録画にもモザイクが映る（エリアが消えて中身が見えることがない） | 共有先側のスクリーンショット |
| PT-11 | 800×450 のエリア（ツールバーのサイズ表示で確認）の下に窓を 3 枚重ね、更新間隔 100 ms で 1 分置く。タスクマネージャの「詳細」で Hider.exe の CPU を見る | CPU が 1 コア換算 10% 以下（例: 8 論理コアなら表示 1.25% 以下） | CPU の値、PC の CPU / GPU、`Hider.exe --verbose 2> hider.log` で起動したログの capture 行（1 回あたりの ms と窓数）を数行 |
| PT-12 | Edge、VS Code、設定アプリ、管理者のコマンドプロンプト、デスクトップ（何も無い所）、排他全画面のゲーム / 動画の上にそれぞれエリアを置く | 正しく取れる窓はモザイク、黒になる窓はパターン（生成）に自動で切り替わり「取得できません」が出る | 窓の種類ごとの結果（モザイク / 自動切替） |
| PT-13 | 設定で更新間隔を 0 にする → 下の内容を変える → 待つ → ↻ を押す → エリアを少し動かす | 0 の間は自動で更新されず、↻ と移動の確定でだけ更新される | 結果メモ |
| PT-14 | 編集モードでエリアを動画の上でゆっくりドラッグし続ける | ドラッグ中も下の内容に追従してモザイクが変わる | 録画 |
| PT-04（追記） | 設定ポップアップ（⚙）で塗りつぶしの透明度を 50% → 100% | 50% で下が半分透ける。100% で完全に隠れる | スクリーンショット 2 枚 |

## Ubuntu 26.04 第 1 段階（Step 7）

録画は GNOME の画面録画（Ctrl+Shift+Alt+R）ではなく、別の PC からのカメラ撮影か OBS（PipeWire 画面キャプチャ、60 fps）で行う。帯の撮影はスクリーンショットのたびに Hider の窓の一部が透明になるため、画面録画自体が帯を写すことに注意。

| ID | 手順 | 合格基準 | 記録するもの |
|---|---|---|---|
| PT-15（後半） | 拡張機能アプリで AppIndicator を無効にして Hider を起動 | 「Hider — エリア n 個」と同じメニュー項目を持つ小窓が出る。× で最小化され、「終了」で終わる | スクリーンショット |
| PT-17 | 動きのない画像（文字の多いページ）の上に 240 px 高のエリア（帯の高さ 8）を置いて ✓。撮り直し中を 60 fps で録画 | コマ送りで、素の内容が見えるのは同時に帯 1 本（8 px）だけ。撮り直し後のモザイクが下の内容と一致する | 録画、撮り直しにかかった秒数 |
| PT-18 | 第 1 段階（Screenshot ポータル）: libhidercap.so を実行ファイルの隣から外す（PT-25 と同じ）。初回: .desktop から起動してエリアを作る → スクリーンショットの許可ダイアログで「許可」。終了して端末から `Hider` で起動し直す | ダイアログは最初の 1 回だけ（端末起動では出ない） | 結果メモ |
| PT-19 | 第 1 段階: libhidercap.so を外したまま、設定 → プライバシー → スクリーンショットの許可を取り消し（または初回ダイアログで「拒否」）、エリアを作る。第 2 段階（libhidercap.so あり）では、ScreenCast のモニタ選択ダイアログで「キャンセル」する | どちらもパターン（生成）に自動で切り替わり、ツールバーに「取得できません」 | スクリーンショット |
| PT-20 | ディスプレイ設定で 125%、150% にして、それぞれエリアを置いて ✓（ピクセル化 12、ぼかし 0） | モザイクのセルの境目が下の内容の位置と合う（目で見てずれなし）。合わない場合はずれの向きと量（px） | スクリーンショット 2 枚、`Hider --verbose` の出力 |

## Ubuntu 26.04 第 2 段階（Step 8）

`Hider --verbose` を端末から起動して行う。第 2 段階の撮影ではログに `screencast: frame …x… seq N, X ms after the strip (pts)` が帯ごとに出る（`(receive time)` と出る場合は Mutter のフレーム時刻が使えていない）。撮影中は GNOME の画面共有表示（上部のオレンジのアイコン）が出て、撮り終えて約 3 秒で消える。

| ID | 手順 | 合格基準 | 記録するもの |
|---|---|---|---|
| PT-21 | 初回: エリアを作る → 画面共有ダイアログでモニタを選び「共有」。Hider を終了して起動し直し、エリアを動かして ✓ | 2 回目以降はダイアログなしで撮れる（~/.hider/restore_token が毎回更新される） | 結果メモ |
| PT-22 | 240 px 高・帯 8 px のエリアで撮り直し、ログの帯ごとの行を見る | 各帯の `ms after the strip` が 3 フレーム以内（60 Hz なら 50 ms 以内）で `(pts)` | ログ 30 行 |
| PT-23 | PT-22 と同じ撮り直しの、最初と最後の `screencast: frame` の時刻差 | 2 秒以内 | 秒数 |
| PT-24 | linux-arm64 実機で PT-15〜23 | 同じ基準 | 機材名と結果 |
| PT-25 | libhidercap.so を実行ファイルの隣から外して起動し、撮り直す | Screenshot ポータル（第 1 段階）で撮れる。ログに `libhidercap.so could not be loaded` | ログの該当行 |
| PT-26 | Firefox（Google Meet 等）と Zoom で画面全体を共有し、モザイクのエリアを置いて撮り直す | 共有先にもモザイクが映り、帯の撮影中も中身が 1 本分を超えて見えない | 共有先のスクリーンショット |
| PT-27（追加） | エリアを 2 枚目のモニタに置き、ダイアログで 1 枚目を選んだ状態で撮り直す | 2 枚目のエリアは第 1 段階で撮れる（ログに `is not on the shared monitor`） | ログの該当行 |

## 作業コンテナでの確認（参考）

Xvfb（コンポジタなし）で、起動時の復元、画面外エリアの主画面中央への補正、ダブルクリックでの編集モード、ツールバー表示（日本語）、本体ドラッグ、Esc での終了と保存を確認済み（2026-10-11）。コンポジタがないため編集時の余白は白く見える（実機では透明）。

Step 7 の帯方式（2026-10-11）: Xvfb + xcompmgr（コンポジタ）+ 専用セッションバス + 偽の Screenshot ポータル（tools/fakeportal、`import -window root` で撮影）で、240 px 高 / 帯 8 px のエリアが 31 回の撮影（初回の許可ダイアログ対策で帯の前に捨てる 1 枚 + 帯 30 本）で下の内容のモザイクになること、撮影 PNG が毎回削除されること（FR-53）、拒否（応答 1）とポータル不在で生成パターンに切り替わること、トレイが無いと D-9 の窓が出ることを確認。トリミング後の単一ファイル（linux-x64）でも同じ。手順は scripts/xvfb-strip-smoke.sh。

Step 8 の第 2 段階（2026-10-11）: 上記に専用の PipeWire + WirePlumber を足し、Xvfb の画面を GStreamer（ximagesrc ! pipewiresink）で映像ノードにして、偽ポータルの ScreenCast から libhidercap で 30 帯すべて撮れること、restore_token が保存され次回の SelectSources に渡り、新しいものに置き換わること、撮り終えて約 3 秒でセッションが閉じることを確認（`scripts/xvfb-strip-smoke.sh --screencast`、CI の Linux GUI ジョブでも実行）。GStreamer の PTS は CLOCK_MONOTONIC ではないため受信時刻で判定され、30 fps の映像で 30 帯 約 2.1 s。
